# 🎭 入局 MYSTERY·STUDIO — 城市剧本杀门店拼场预约与主持排班平台

一个面向城市剧本杀门店的一体化运营页面：玩家选本预约拼场 → 门店按人数/房间/主持档期与熟练度排班成局 → 到店后签到、分角、道具押金、主持开场、休息、结账全流程推进 → **开场前主持缺勤/场次延迟/房间不可用时，门店不是简单取消，而是「名额冻结 → 可解释改期方案（同日换场/跨店迁移/全额退款/保留权益）→ 玩家确认倒计时 → 原场次名额、目标房间、主持班次、剧本库存一次性锁定，并发失效整体回滚 → 候补按公开规则递补」** → 迟到/退出/换本/不适/结账争议等异常以工单串联玩家确认、前台签到、主持排班、店长审批与收退款 → 结束后收集评价、主持表现、剧本难度与道具损耗，反哺下一轮排班与剧本推荐。

技术栈：**React 18 + TypeScript + Vite + Zustand（persist 本地持久化）**，纯前端单页应用，Nginx 托管静态资源，无外部数据库依赖（演示数据内置，可一键重置）。

---

## 原始需求

> 设计城市剧本杀门店拼场预约与主持排班页面，可使用 React、TypeScript 和 Zustand。玩家选择剧本时，页面展示人数、时长、恐怖程度、推理难度、角色性别建议、是否适合新手、开场时间和退款规则，并采集玩家人数、角色偏好、是否接受反串和联系方式。门店根据拼场人数、房间、主持人档期和剧本熟练度生成场次。到店后，前台签到、角色分配、道具发放、主持开场和中途休息状态都在页面中推进。若玩家迟到、拼场人数不足、有人临时退出、主持人请假、玩家要求换本、体验中途不适或结账争议，页面要把玩家确认、前台签到、主持排班、店长审批和收退款记录归到场次。结束后，页面收集玩家评价、主持表现、剧本难度和道具损耗，帮助门店调整排班和剧本推荐。页面还要支持会员拼场、包场、生日局、恐怖本安全提示和道具押金。店长查看场次时，需要知道人数是否成局、主持是否熟练、房间是否空闲、玩家是否已支付和退款风险；玩家体验不好时，客服能把签到、角色、主持中断和道具问题串起来处理。道具损耗、玩家复购和主持复盘会反过来影响下一轮剧本排期。

## 一键启动（宿主 docker compose up）

前置：宿主已安装 Docker Engine（含 compose 插件）。

```bash
# 在项目根目录（含 docker-compose.yml）执行
cp .env.example .env          # CC_PUBLISH_PORT 可按环境修改，默认 3211
docker compose up -d --build
```

查看实际映射端口并访问：

```bash
docker compose port app 8080
# 例如输出 0.0.0.0:3211，则浏览器访问 http://host.docker.internal:3211
```

停止与清理：

```bash
docker compose down
```

说明：
- compose **只发布应用端口**（`${CC_PUBLISH_PORT}:8080`），无数据库/缓存等依赖服务端口对外暴露；
- 容器内非 root 用户（uid 101）运行，镜像内含 `HEALTHCHECK`（`/healthz`）；
- 数据保存在浏览器 LocalStorage（Zustand persist），右上角「↺ 重置演示」可随时恢复内置演示数据。

### ⭐ 新特性推荐演示路径（开场前异常处置，约 6 分钟）

> 入口：右上角切到「店长」→ 导航「异常处置中心」（默认已打开 `d-demo-1`）。

1. **查看异常**：处置单显示缺勤原因、受影响玩家/拼车组、需人工介入事项；场次 `ss-demo-2` 已冻结为「待补位」（去「场次推进」能看到其名额仍保留、可售/候补状态未丢，且不能被直接解散）。
2. **计算候选方案**：点「计算候选方案」，系统给出同日 15:30/21:30 换场、滨江店跨店迁移、全额退款、保留权益 4 类候选，每个候选列出：
   - 命中原因（房间容量、主持熟练度 ≥3、盒装本库存、可迁移人数与会员构成）；
   - 冲突解释（如某同行组只接受 21:30 → 整组不可随其他时段迁移；某候选主持熟练度不达标等）；
   - 角色预分配（按角色性别建议 + 反串意愿逐人配角，防止角色配置失衡）。
3. **发布方案**：选「同日换场 21:30」发布，30 分钟确认倒计时开始；切到「玩家 → 我的拼场」可看到方案卡：**倒计时每秒跳动**、新安排、权益说明（平移不二次扣款）、接受 / 仅指定时段 / 拒绝。
4. **回到店长端代回复**（表格支持电话代确认）：可让 6 人全部接受，或让陈默组拒绝（观察拒绝策略：全额退款 / 保留权益待补位的切换）。
5. **确认迁移（原子事务）**：
   - 正常确认 → 一次性出现 4 把资源锁「原场次名额 / 目标房间 / 主持人班次 / 剧本库存」并提交；6 人迁入 `ss-demo-3`、费用平移、自动配角；事件时间线完整留痕。
   - **并发回滚验证**：再次重置演示后重走 1-4，在执行区选择「模拟盒装本库存被并发开新场耗尽」（或房间/主持/名额抢占）→ 确认失败，4 把锁中 1 失败、3 回滚，**原场次仍是待补位、玩家流水净额一分未变**；随后可重新计算/发布方案并成功执行。
   - **幂等验证**：迁移成功后再次点击确认，直接返回同一结果，不新增锁、不重复退款；台账中退款流水带 `planId + playerId` 幂等键。
6. **候补递补**：处置详情下方候补面板按公开分值排序；对李大壮点「通知补位」19:00 场会被系统拒绝（仅接受 21:30）；通知顾晓萌补 21:30，玩家端出现 15 分钟补位倒计时，接受后自动成局（有保留权益时自动核销，无重复扣款）；可把韩梅的通知留在那里，到点未响应会由系统标记「超时未响应」并顺延（也可在真实时间到达截止后自动发生）。
7. **手工调整约束**：点「置顶/手工补位」必须填写原因；即使置顶，容量与角色人数/性别约束仍由系统强制校验，无法绕过。
8. **全程时间线**：处置详情与场次档案中的「场次事件时间线」覆盖 异常触发 → 方案计算 → 玩家确认 → 资源锁定 → 退款/补偿 → 排班变更 → 候补递补。

### 历史流程演示路径（签到→结账→复盘）

1. **玩家** → 剧本大厅 → 打开《红嫁衣》查看恐怖安全提示与退款规则 → 提交 4 人拼场预约（逐人填写性别、偏好/反串、11 位手机号，勾选安全确认，在线预付）。
2. **前台** → 排班成局台（日期 2026-09-23）→ 看到拼场池 →「按拼场生成场次」（人数不足会被系统拦截并给出原因；可再造一单凑够人数）→ 系统自动匹配房间、按档期+熟练度选派主持。
3. 打开 **ss-demo-1** 场次：给孙然「到店收款」→ 全员签到 → 一键分角 → 发道具收押金 → 主持开场 → 中途休息 → 道具回收时把「情书信封」登记为「严重损耗」（自动生成扣押金工单）→ 结账（自动退剩余押金）。
4. 途中点「中途不适 / 结账争议 / 临时退出」等按钮开工单 → 切**客服**看串联档案 →「玩家确认，提交店长审批」→ 切**店长**核定金额 → 审批通过 → 到「收退款」看流水全部归到场次与工单。
5. 切**店长 → 复盘与反馈**：收集玩家评价（主持表现自动计入主持均分）→ 主持复盘调整熟练度 → 再到「推荐与排期调权」看到道具损耗/评价/熟练度如何改变推荐分与排期动作。
6. **店长看板**：成局/异常/候补/支付/退款风险指标，风险与需人工介入场次一键跳转处置。

## 开场前异常处置 · 需求覆盖对照（本次特性）

| 需求点 | 实现位置 |
| --- | --- |
| 异常不是简单取消：同时处理玩家/候补/主持排班/房间/库存/会员权益 | 「异常处置中心」`triggerDisruption`：场次转「待补位」冻结名额（保留可售/候补状态），缺勤主持释放班次+登记请假，故障房登记 downSlots，同步工单与事件 |
| 店长发起四种方案：同日换场 / 跨店迁移 / 全额退款 / 保留权益待补位 | `computePlans` 一次产出 4 类候选，覆盖本店当日其他开场、其他门店、退款、权益保留 |
| 方案先计算可接受时段、角色偏好、拼车/同行关系、会员优先级、房间容量、主持技能 | 候选构建：玩家 acceptableSlots 过滤、同行组整组判定（不拆车）、会员加权排序、容量/剧本上限校验、主持档期+熟练度≥3、盒装本库存校验、`matchRoles` 性别/反串逐人配角 |
| 可解释候选安排 | 每个候选带 `reasons`（命中点）与 `conflicts`（冲突点，精确到玩家/资源），页面逐条展示 |
| 确认迁移一次性锁定四类资源 | `confirmMigration` 同事务校验并创建 4 把 `ResourceLock`：原场次名额、目标房间、主持人班次、剧本库存 |
| 任一资源并发失效 → 整体回滚，保留原场次可售/候补 | 任一锁失败：失败锁+回滚锁全部落账，方案标记「执行失败已回滚」，原场次保持待补位，玩家流水/权益不变；执行区可注入 4 类并发抢占模拟 |
| 不能已扣权益却无座位 | 先锁后扣：费用随席位平移（无二次扣款），拒绝/超时玩家才按策略退款或保留权益；容量与角色约束在确认时二次终检 |
| 候补公开优先级规则 | `computeWaitScore`（页面公开）：金卡40/银卡25、自动补位20/指定时段5、报名先后（0.1/分钟封顶20）、到店次数（封顶10）、同行成组5 |
| 区分 同意自动补位 / 仅指定时段 / 超时未响应 | `WaitlistEntry.mode` + `status`：通知 15 分钟倒计时，`tick()` 自动把超时改「超时未响应」并释放名额顺延；仅指定时段不可被派到其他时段 |
| 店长手工调整填原因且不绕过约束 | 置顶/手工补位强制原因留痕（`manualPin`/事件），容量、角色人数/性别校验在 `notifyWaitlist/respondWaitlist` 中照常强制 |
| 玩家端实时看到方案、确认倒计时、权益变化、失败原因 | 「我的拼场」`PlayerPlanCard`：每秒倒计时、安排与权益说明、回滚失败原因、逐玩家确认按钮；候补卡含顺位/分值/15 分钟倒计时；权益变动表 |
| 店长端看到冲突资源、候补排序、需人工介入 | 处置详情：候选冲突、锁台账、候补排序与分值分解、`manualAlerts` 人工介入清单；看板顶部异常/候补指标 |
| 事件时间线（六类事件） | `IncidentEvent` + `disruptionTimeline`：异常触发/方案计算/玩家确认/资源锁定/退款补偿/排班变更/候补递补，处置详情与场次档案双入口 |
| 防重复确认/延迟通知/多店抢占导致超卖、重复退款、角色失衡 | 执行幂等（已执行直接返回）；退款 `planId+playerId` 去重；锁参与房间/主持/库存占用计算（跨店同表判定）；配角失败即拒绝迁移 |
