# 🎭 入局 MYSTERY·STUDIO — 城市剧本杀门店拼场预约与主持排班平台

一个面向城市剧本杀门店的一体化运营页面：玩家选本预约拼场 → 门店按人数/房间/主持档期与熟练度排班成局 → 到店后签到、分角、道具押金、主持开场、休息、结账全流程推进 → 迟到/人数不足/退出/主持请假/换本/不适/结账争议等异常以工单串联玩家确认、前台签到、主持排班、店长审批与收退款 → 结束后收集评价、主持表现、剧本难度与道具损耗，反哺下一轮排班与剧本推荐。

技术栈：**React 18 + TypeScript + Vite + Zustand（persist 本地持久化）**，纯前端单页应用，Nginx 托管静态资源，无外部数据库依赖（演示数据内置，可一键重置）。

---

## 原始需求

> 设计城市剧本杀门店拼场预约与主持排班页面，可使用 React、TypeScript 和 Zustand。玩家选择剧本时，页面展示人数、时长、恐怖程度、推理难度、角色性别建议、是否适合新手、开场时间和退款规则，并采集玩家人数、角色偏好、是否接受反串和联系方式。门店根据拼场人数、房间、主持人档期和剧本熟练度生成场次。到店后，前台签到、角色分配、道具发放、主持开场和中途休息状态都在页面中推进。若玩家迟到、拼场人数不足、有人临时退出、主持人请假、玩家要求换本、体验中途不适或结账争议，页面要把玩家确认、前台签到、主持排班、店长审批和收退款记录归到场次。结束后，页面收集玩家评价、主持表现、剧本难度和道具损耗，帮助门店调整排班和剧本推荐。页面还要支持会员拼场、包场、生日局、恐怖本安全提示和道具押金。店长查看场次时，需要知道人数是否成局、主持是否熟练、房间是否空闲、玩家是否已支付和退款风险；玩家体验不好时，客服能把签到、角色、主持中断和道具问题串起来处理。道具损耗、玩家复购和主持复盘会反过来影响下一轮剧本排期。

## 一键启动（宿主 docker compose up）

前置：宿主已安装 Docker Engine（含 compose 插件）。

```bash
cd 111-b
cp .env.example .env          # CC_PUBLISH_PORT 可按环境修改
docker compose up -d --build
```

查看实际映射端口并访问：

```bash
docker compose port app 8080
# 例如输出 0.0.0.0:3211，则浏览器访问 http://host.docker.internal:3211
```

停止与清理：

```bash
docker compose down
```

说明：
- compose **只发布应用端口**（`${CC_PUBLISH_PORT}:8080`），无数据库/缓存等依赖服务端口对外暴露；
- 容器内非 root 用户（uid 101）运行，镜像内含 `HEALTHCHECK`（`/healthz`）；
- 数据保存在浏览器 LocalStorage（Zustand persist），右上角「↺ 重置演示」可随时恢复内置演示数据。

## 角色与演示账号（进入页面后在右上角切换角色）

本系统为门店运营演示，不设登录密码，通过**角色切换**进入不同工作台（各角色权限按钮自动显隐）：

| 角色 | 入口 | 可做的事 |
| --- | --- | --- |
| **玩家** | 剧本大厅 / 我的拼场 | 浏览 5 个剧本（含人数/时长/恐怖程度/推理难度/性别建议/新手适配/开场时间/退款规则/押金/安全提示）；提交拼场、包场、生日局预约；填写人数、每位玩家角色偏好（C位/推理位/情感位…）、是否接受反串、手机号；在线预付或到店付；取消预约自动退款 |
| **前台** | 场次推进 / 排班成局台 / 异常工单 / 收退款 | 按拼场池生成场次；前台签到、登记迟到、到店收款、临时退出（自动生成退款工单）；角色分配（手动/按偏好一键）；道具发放收押金、回收验收登记损耗；推进开场/休息/结账；发起各类异常工单 |
| **主持人** | 我的场次 / 主持复盘 | 查看派给自己的场次与熟练度；记录主持中断；结账后提交复盘（熟练度 ±1，影响下轮排班） |
| **店长** | 店长看板 / 排班成局台 / 场次推进 / 工单审批 / 复盘与反馈 / 推荐与排期调权 / 收退款 | 看板：人数是否成局、主持是否熟练、房间是否空闲、支付情况、退款风险敞口；审批工单并核定退款/扣押金金额（自动写流水）；解散场次全额退款；查看道具损耗/复购榜/排期建议 |
| **客服** | 客服工单串联 / 场次档案 | 一张工单内看到完整链路：玩家签到、角色、主持中断、道具问题、支付与退款；登记跟进、取得玩家确认后提交店长审批 |

### 演示数据（预置，开箱即看点）

- 剧本 5 个：《雾港惊魂夜》（重恐）、《长安十二时辰局》（烧脑）、《那年夏天的情书》（情感/新手）、《欢乐麻将馆》（欢乐/新手）、《红嫁衣》（中恐，含安全词提示）。
- 房间 5 间、主持 3 位（阿哲-金牌 / 小鹿-资深 / KK-初级，各有剧本熟练度 0-5）、会员 3 位（含金卡会员林小夏 13800000001）。
- **已成局场次 `ss-demo-1`**：《那年夏天的情书》2026-09-23 19:30 生日局，教室房 + 主持小鹿，已走到「角色已分」；3 人已签到已付、第 4 人「孙然」迟到未付——可直接体验：登记迟到→催付→发道具→开场→休息→回收道具→结账→复盘。
- **进行中工单 `t-demo-1`**：孙然迟到，内含前台/主持处理时间线，可切换到店长完成审批闭环。

### 推荐演示路径（约 5 分钟走完全部需求）

1. **玩家** → 剧本大厅 → 打开《红嫁衣》查看恐怖安全提示与退款规则 → 提交 4 人拼场预约（填偏好/反串/手机号，勾选安全确认，在线预付）。
2. **前台** → 排班成局台（日期 2026-09-23）→ 看到拼场池 →「按拼场生成场次」（人数不足会被系统拦截并给出原因；可再造一单凑够人数）→ 系统自动匹配房间、按档期+熟练度选派主持。
3. 打开 **ss-demo-1** 场次：给孙然「到店收款」→ 全员签到 → 一键分角 → 发道具收押金 → 主持开场 → 中途休息 → 道具回收时把「情书信封」登记为「严重损耗」（自动生成扣押金工单）→ 结账（自动退剩余押金）。
4. 途中点「中途不适 / 结账争议 / 临时退出」等按钮开工单 → 切**客服**看串联档案 →「玩家确认，提交店长审批」→ 切**店长**核定金额 → 审批通过 → 到「收退款」看流水全部归到场次与工单。
5. 切**店长 → 复盘与反馈**：收集玩家评价（主持表现自动计入主持均分）→ 主持复盘调整熟练度 → 再到「推荐与排期调权」看到道具损耗/评价/熟练度如何改变推荐分与排期动作。
6. **店长看板**：成局/熟练/房间/支付/退款风险五项指标与风险场次列表。

## 需求覆盖对照

| 需求点 | 实现位置 |
| --- | --- |
| 剧本展示人数/时长/恐怖/推理难度/性别建议/新手/开场时间/退款规则 | 玩家端「剧本大厅」卡片 + 预约弹窗详情 |
| 采集玩家人数、角色偏好、接受反串、联系方式 | 预约表单（逐玩家偏好与反串、11 位手机号校验） |
| 按拼场人数/房间/主持档期/熟练度生成场次 | 「排班成局台」`generateSession`：成局区间校验、房间容量+时段冲突过滤、主持档期过滤后按熟练度排序自动选派；无房/无主持/不熟练自动开工单 |
| 签到/分角/道具发放/主持开场/中途休息状态推进 | 场次详情九段状态机 + 逐步操作按钮 |
| 迟到/人数不足/退出/主持请假/换本/不适/结账争议 | 场次内快捷工单 + 玩家行操作（迟到、退出自动按 70% 生成退款工单） |
| 玩家确认/前台签到/排班/店长审批/收退款归场次 | 工单时间线 + SessionTrace 串联档案 + `approveTicket` 自动写收退款流水（场次号/玩家/工单号三关联） |
| 玩家评价/主持表现/剧本难度/道具损耗 | 复盘页 ReviewForm（主持分回写主持均分）、道具回收损耗台账 |
| 会员拼场/包场/生日局/恐怖安全提示/道具押金 | 预约局类型三选一（金/银卡折扣、寿星标记）、重恐/中恐安全词「开灯」强制确认、发道具收押金/结账退押金 |
| 店长五问（成局/熟练/房间/支付/退款风险） | 店长看板四指标卡 + 风险场次徽章 + `sessionRisk` |
| 客服串联签到/角色/主持中断/道具问题 | 工单详情中的场次串联档案 |
| 损耗/复购/主持复盘反哺排期与推荐 | 「推荐与排期调权」页：损耗降权维修、差评偏难降权、高复购好评加场、熟练度 ±1 改变排班选派与推荐分；会员复购 +1（结账时） |

## 目录结构

```
src/
  types.ts          # 全部领域类型（剧本/主持/房间/会员/预约/场次/工单/流水/评价/复盘）
  seed.ts           # 内置剧本、角色表、道具、主持、房间、会员及演示场次/工单/流水
  store.ts          # Zustand store：预约、排班成局、状态机、工单审批、收退款、复盘反馈、派生选择器
  ui.tsx            # 徽章/弹窗/星级等通用组件
  App.tsx           # 角色切换 + 导航
  pages/            # 玩家端 / 排班台 / 场次推进 / 工单中心 / 看板 / 台账 / 复盘 / 推荐
Dockerfile          # 多阶段构建（node:22 构建 → nginx-unprivileged 运行，USER 101 + HEALTHCHECK）
docker-compose.yml  # 仅发布 ${CC_PUBLISH_PORT}:8080
nginx.default.conf  # SPA 回退 + /healthz
.env.example
```
